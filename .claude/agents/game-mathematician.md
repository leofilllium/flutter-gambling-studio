## M1 — Paytable RTP (C1: слоты, покер, блэкджек, рулетка, бинго)

### Расчёт весов символов

Для каждого символа определяете:
- **Вес** (Weight): целое число, чем больше — тем чаще выпадает
- **Частота**: Weight / Sum(all weights)
- **Шанс комбинации x3**: (W/ΣW)³

```
Символ    | Вес | Частота | Шанс x3   | Множитель | Вклад в RTP
----------|-----|---------|-----------|-----------|------------
Вишня     |  40 | 40%     | 6.40%     | x2        | 12.80%
Лимон     |  30 | 30%     | 2.70%     | x3        | 8.10%
Колокол   |  15 | 15%     | 0.34%     | x10       | 3.38%
```

### Формула RTP

```
RTP = Σ (P(combo_i) × Multiplier_i × Bet)
    = Σ ((W_i / ΣW)^reels × Payout_i)
```

Целевой RTP 95–97%. Итерируйте веса и выплаты; hit rate двигается ступенчато
(он зависит от того, КАКИЕ комбинации платят, а не сколько), поэтому сначала
подберите набор платящих комбинаций, затем — суммы.

### Волатильность

| Волатильность | RTP | Частота побед | Макс. выплата |
|---------------|-----|---------------|---------------|
| Низкая        | 96.5% | ~35%        | x50           |
| Средняя       | 96%   | ~25%        | x200          |
| Высокая       | 95%   | ~15%        | x1000         |

### Обязательно проверить

- Каждый **bet-tier** отдельно: RTP не должен зависеть от размера ставки.
- **Бонус-режим** считается в общем RTP; в отчёте указывается доля базовой игры и бонуса
  (типично 60/40 или 70/30).
- Максимальный выигрыш достижим за 1М раундов (иначе это фикция).

## M2 — Instant-Win RTP (C2: crash, mines, dice, hi-lo, tower, keno, скретч, pick)

### Общая формула «оригиналов»

```
множитель(шаг) = (1 - house_edge) / P(дожить до шага)
RTP = 1 - house_edge
```

Для mines с `n` ячеек, `m` мин, после `k` открытий:
```
P(k) = C(n-m, k) / C(n, k)
multiplier(k) = (1 - house_edge) / P(k)
```

### Инвариант, который вы обязаны защищать

**RTP не зависит от стратегии игрока.** Одинаков для любой точки cash-out, любой глубины,
любого порога. Разброс > 0.001 между стратегиями означает утечку — обычно в капе
максимального множителя или в округлении выплаты.

Если кап реально нужен — ограничьте пространство стратегий (`max_picks`), а не молча
режьте выплату на глубине.

### Детерминизм раунда

Исход обязан выводиться из `serverSeed + clientSeed + nonce` ДО анимации.
Ваша зона: проверить, что формула исхода зависит от всех трёх и воспроизводима.

## M3 — Economy (C3: spin-to-progress гибриды)

Это не RTP, а сходимость экономики. Что вы балансируете:

| Метрика | Целевое |
|---------|---------|
| Source/sink ratio (приход / расход на анлоки) | 0.90–1.15 |
| Пейс прогресса (сессий до анлока) | 2–5 |
| Длина сессии (до исчерпания энергии) | 3–7 минут |
| Регенерация энергии | покрывает 2–3 сессии в сутки |
| Шаг цены анлока N+1 / N | ≤ 1.6× |
| Dead-end rate (сессий без продвижения) | < 10% |

**Ключевой приём**: доход обязан расти вместе с прогрессом
(`income_growth_per_unlock`). Плоский доход против геометрических цен всегда
превращается в гринд-стену, как бы вы ни двигали цены.

Таблица событий спина (монеты / щит / атака / набег / джекпот) — тоже ваша:
веса объявляются в конфиге и суммируются в 100%.

## M4 — Gacha (C4)

| Параметр | Целевое |
|----------|---------|
| Base rate редчайшей редкости | 0.5–2.0% |
| Hard pity | 50–90 пуллов |
| Сумма вероятностей редкостей | ровно 1.0 |
| Эффективный rate (с учётом pity) | ≥ base rate, совпадает с расчётом ±0.1 п.п. |
| 90-й перцентиль пуллов до редкости | ≤ hard pity |
| Пропусков pity | 0 |

**Soft pity** — рост шанса начиная с ~75% от hard pity. Он сглаживает «боль»
и в реальности повышает эффективный rate заметно выше объявленного base rate:
именно эффективный rate раскрывается игроку рядом с базовым.

**Дубликаты обязаны иметь ценность.** Пулл, дающий «ничего», — это провал дизайна,
и вы обязаны сказать об этом дизайнеру, а не компенсировать числами.

## M5 — Run Win-Rate (C5: казино-рогалики)

| Параметр | Целевое |
|----------|---------|
| Run win-rate у «среднего игрока» | 25–40% |
| Шаг цели раунда | ≤ 2× |
| Длина забега | 8–20 минут |
| Доминирующих модификаторов | 0 |
| Мёртвых модификаторов | 0 |
| Детерминизм по seed | обязателен |

Win-rate здесь — **очень чувствительная** функция: рост силы игрока и рост целей
оба экспоненциальны, поэтому небольшой сдвиг дохода переводит забег из «непроходимо»
в «тривиально». Двигайтесь мелкими шагами и всегда проверяйте прогоном.

Модификаторы оцениваются **относительно медианы набора**, а не по абсолютному порогу:
вопрос дизайна — «остаётся ли выбор осмысленным», а не «выигрывает ли модификатор в одиночку».

> C5 — единственная модель, где `Random.secure()` НЕ обязателен: забег должен
> воспроизводиться по seed. Это фиксируется в ADR.

## M6 — Physics RTP (C6: plinko, пачинко, coin pusher)

Аналитически считается только plinko (доска Гальтона — точное биномиальное распределение).
Пачинко и coin pusher — только эмпирический замер из headless-прогона игры.

| Параметр | Требование |
|----------|------------|
| RTP | 95–97% |
| Timestep | фиксированный (1/60), не привязан к fps |
| Seed стартовых условий | детерминированный |
| «Мёртвые» корзины (< 0.1% попаданий) | отсутствуют |

**Ловушка coin pusher**: накопление монет на полке делает RTP нестационарным.
Замер обязателен в установившемся режиме — после ≥10 000 прогревочных монет,
а не с пустого поля.

### Запрещено

- Менять целевую метрику (RTP / pity / win-rate) без ADR — только через `/architecture-decision`
- Проектировать без прогона: «наверное сбалансировано» не вердикт
- Создавать модели с RTP ниже 90% — это нечестно по отношению к игроку
- Дублировать числа модели в Dart-коде: единственный источник правды — JSON-конфиг
- Коммитить конфиг без обновления `simulation.last_run_date`
- Молча «чинить» метрику капом или округлением — это утечка, а не баланс
- Допускать расхождение между числами в конфиге и числами, показанными игроку
  на paytable / экране шансов (`.claude/rules/responsible-gaming.md` §5)

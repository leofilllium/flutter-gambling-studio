# Layout Archetypes — Композиционное разнообразие экранов

> **Проблема, которую это решает:** даже с уникальным Design DNA (цвета/шрифты/формы)
> игры выходят похожими, потому что КОМПОЗИЦИЯ экранов всегда одна и та же:
> HUD сверху, большая кнопка по центру снизу, меню — вертикальный столбик кнопок.
> 5 вариантов структуры (`directory-structure.md`) меняют, ГДЕ лежат файлы — но не то,
> как экран ВЫГЛЯДИТ. Этот документ добавляет разнообразие именно компоновки.

**Layout Archetype** — это система расположения элементов (где HUD, где основное действие,
как собрано меню, как входят оверлеи). Art Direction (палитра, шрифты, формы) приходит из
**Design DNA** концепта. Эти две оси независимы: один и тот же layout-архетип с разным DNA
даёт совершенно разные игры, и наоборот.

```
Игра = Layout Archetype (КАК скомпоновано)  ×  Design DNA (КАК выглядит)  ×  Архетип A–AF (ЧТО за механика)
```

При `/autocreate` layout-архетип выбирается псевдослучайно (как и структура) и записывается
в `design/art-direction.md`. `ui-programmer` читает его и компонует экраны соответственно.

---

## Инварианты (соблюдаются в ЛЮБОМ архетипе)

Архетип меняет композицию, но НЕ нарушает базовый UX:

- Основное действие — в зоне досягаемости большого пальца (нижние 60% экрана на мобильном).
- Tap target ≥ 48×48 у всех интерактивных элементов.
- SafeArea на каждом экране, кроме fullscreen GameScreen.
- Игровое поле остаётся главным фокусом игрового экрана (≈60% площади).
- Визуальная иерархия: основное действие — самый заметный элемент.
- Навигация назад работает с каждого экрана.

---

## L1 — Classic Stack (Верхний HUD / Нижняя панель)

Привычная мобильная раскладка. Безопасный выбор по умолчанию.

- **Main Menu:** герой-логотип сверху по центру → вертикальный столбик кнопок под ним. ИГРАТЬ — крупная, доминирующая.
- **Game Screen:** тонкий HUD-бар закреплён сверху (баланс/счёт/настройки), игровое поле в центре, панель управления + основное действие закреплены снизу.
- **Action button:** по центру нижней панели, самый крупный элемент.
- **Overlays:** toast снизу над панелью; модалки — по центру с лёгким затемнением фона.
- **Transitions:** плавный fade-through или slide-up.

## L2 — Bottom Command Deck (Нижняя консоль)

Вся «приборная панель» собрана в плотную нижнюю консоль; поле тянется до краёв сверху.

- **Main Menu:** крупный арт/сцена сверху (≈55%), снизу — «выезжающая» панель режимов (bottom sheet) с кнопкой старта.
- **Game Screen:** игровое поле edge-to-edge сверху, внизу — выраженная консоль-дек с HUD, ставкой/управлением и основным действием как единый блок.
- **Action button:** встроена в дек, выделена цветом/размером относительно соседей.
- **Overlays:** выезжают из дека вверх; модалки — bottom sheet со скруглённым верхом.
- **Transitions:** sheet slide-up, dек «дышит» при переходах.

## L3 — Floating Corners (Минимальный chrome)

Никаких баров. Маленькие «плавающие» виджеты по углам, поле — full-bleed.

- **Main Menu:** full-bleed арт/сцена на весь экран, одна центральная CTA, мелкие иконки настроек/инфо в углах.
- **Game Screen:** поле занимает весь экран; баланс/счёт — плавающий чип в верхнем углу, настройки — в противоположном, основное действие — крупная плавающая кнопка (FAB-стиль) внизу по центру или в углу для большого пальца.
- **Action button:** плавающая, с заметной тенью/обводкой, чтобы читаться поверх поля.
- **Overlays:** всплывают из соответствующего угла; модалки — компактные карточки по центру.
- **Transitions:** scale/fade от точки появления.
- ⚠️ Контраст плавающих элементов к полю обязателен (подложка/обводка/тень) — иначе нечитаемо.

## L4 — Side Rail (Боковая панель)

Вертикальная панель сбоку держит управление/HUD; поле занимает остальное. Хорошо для широких экранов и веб.

- **Main Menu:** заголовок и подзаголовок выровнены по левому краю, справа/слева — рейка пунктов меню.
- **Game Screen:** узкий вертикальный rail у одного края (HUD + основное действие + быстрые кнопки), игровое поле — оставшаяся ширина.
- **Action button:** вверху или в центре рейки, визуально крупнее остальных кнопок рейки.
- **Overlays:** выезжают со стороны рейки; модалки — по центру поля.
- **Transitions:** горизонтальный slide, рейка остаётся стабильной.
- ⚠️ На узком портрете rail не должен съедать игровое поле — делай его компактным или сворачиваемым.

## L5 — Split Panel (Две зоны)

Экран явно разделён на две зоны с разными поверхностями.

- **Main Menu:** верхняя зона — арт/превью, нижняя зона (другая поверхность) — меню режимов.
- **Game Screen:** верхние ≈60% — игровое поле, нижние ≈40% — информационная панель с отдельной поверхностью (правила/история/управление + основное действие).
- **Action button:** в инфо-панели, акцентная.
- **Overlays:** разворачиваются в нижней панели или поверх обеих зон для крупных событий.
- **Transitions:** зоны могут анимироваться раздельно (cross-fade верх, slide низ).

## L6 — Card / Sheet Stack (Карточки)

Контент живёт на скруглённых «карточках»/листах, которые сменяют друг друга.

- **Main Menu:** горизонтальная карусель карточек-режимов; свайп выбирает режим, тап — старт.
- **Game Screen:** игровое поле на основной карточке; тонкая «пилюля» HUD сверху; управление — на плавающем листе снизу.
- **Action button:** на нижнем листе либо как акцент на самой карточке.
- **Overlays:** новые карточки наезжают поверх стопки; модалки — поднимающийся лист.
- **Transitions:** карточки сдвигаются/наезжают (shared-axis), depth через тени слоёв.

## Как выбирается архетип (в /autocreate)

В Фазе 2 наряду со структурой проекта выбирается layout-архетип:

```python
import time
layout = ["L1", "L2", "L3", "L4", "L5", "L6"][(int(time.time() // 7) % 6)]
```

Записывается в `design/art-direction.md`. Если идёт `--from-concept`, берётся из секции
**Layout & Composition Direction** концепта (см. `auto-idea`).

> **Не путать с DNA.** Архетип говорит «HUD снизу в деке», DNA говорит «дек — тёплое
> дерево с латунными кнопками» или «дек — холодный матовый металл с подсветкой». Сначала
> выбери композицию (архетип), затем одень её в DNA. Никогда не применяй один и тот же
> art-стиль (неон/стекло) ко всем играм — это и есть slop.

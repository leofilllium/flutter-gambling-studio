# Learning proposal: Require runtime proof before UI audit PASS

Status: proposed; human review and merge required.

## Observed problem

The UI audit issued PASS after source tests while live phone gameplay was bottom-aligned and four configured outcomes rendered letter fallbacks because their asset paths were null.

## Proposed improvement

Require integrated idle and active runtime captures before PASS, verify field placement/dead-zone balance and exact configured visual asset coverage, and use RUNTIME PENDING when execution is deferred.

Base commit: `7fe6ab6b3e35a23035c31a3783c3d802c9f0d260`

    Observation (2026-09-16): A generated Flutter slot received a Phase 8 UI PASS after source review and widget tests, while the actual phone runtime had two release-visible defects.

    Reproduction evidence:
    - The compact gameplay widget explicitly used bottom-center alignment for the reel surface. The test asserted field width and combined board-plus-controls height but did not compare the usable gaps above and below the field. A 390x844 runtime capture showed the field pressed toward the bottom with a large unexplained upper dead zone.
    - Four of ten configured symbol records had null asset paths. The content test collected paths with a null-filtering operation before checking existence, so missing per-symbol coverage disappeared from the assertion. Runtime rendered letter fallbacks for those outcomes.
    - The audit report still said PASS while stating that live Chrome visual capture was deferred.

    Verified correction in the active game:
    - Centered the reel field in the usable region and added a regression check comparing upper/lower gaps within two logical pixels.
    - Added four real raster symbols; removed text fallback; added exact configured-ID-to-runtime-sprite parity and non-null file checks.
    - Live WebGL Chrome captures at 360x640, 390x844, and 1440x900 show centered gameplay and illustrated symbols with zero captured console errors.

    Reusable root cause: the UI audit's mandatory verification stage runs static analysis and widget tests but does not require integrated runtime screenshots before issuing PASS. Source tests can validate the wrong geometry or silently omit incomplete data. Improvement: make final PASS contingent on live idle and active gameplay evidence at phone baseline plus one expanded viewport, explicitly checking field placement/dead-zone balance and one-to-one configured visual asset coverage. If runtime evidence is deferred or unavailable, report RUNTIME PENDING rather than PASS.

# Learning proposal: Require runtime composite evidence in asset review

Status: proposed; human review and merge required.

## Observed problem

Source PNG and contact-sheet checks allowed a PASS while runtime symbol transforms distorted aspect ratios and the shipped character missed explicit reference and placement requirements.

## Proposed improvement

Require representative runtime composite inspection, explicit reference/placement comparison, and aspect-ratio verification before a runnable project's final asset PASS; otherwise mark runtime checks pending.

    Observed 2026-09-16 in Codex of Aaru visual repair.

    The asset review report marked the generated character and reel symbols PASS after inspecting source PNGs, contact sheets, alpha, and isolated 64 px renders. Runtime screenshots later showed two failures that those checks could not detect:

    1. Square symbol PNGs were rendered into tall reel-cell bounds, changing their aspect ratios and visibly stretching the art.
    2. The menu character did not match the user's explicit character reference and was positioned off-center in the phone composition.

    After correction, runtime screenshots at 360x640, 390x844, and 1440x900 verified contained symbol aspect ratios and the reference-derived character's placement. A source-only/contact-sheet-only asset PASS was therefore insufficient for assets already wired into a runnable game.

    Reusable remedy: before a final PASS on a runnable project, the asset-review workflow must inspect representative runtime composites at the canonical phone viewport and one materially different viewport. It must explicitly compare any user-supplied identity/placement reference against the shipped character and verify that runtime transforms preserve sprite aspect ratio. If runtime execution is not yet available, the report must label these checks pending rather than claiming a final PASS.

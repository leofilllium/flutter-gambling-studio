# Learning proposal: Separate elapsed timing from calendar reward clocks

Status: proposed; human review and merge required.

## Observed problem

DateTime-based spin debounce blocks play after device clock rollback; zero-second recovery cooldown also blocks because a negative wall-clock interval is compared to zero.

## Proposed improvement

Clarify existing interaction timing guidance: use monotonic elapsed time for debounce, keep UTC calendar clocks for daily grants, and explicitly bypass disabled cooldown gates; add rollback regression guidance.

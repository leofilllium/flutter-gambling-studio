# Learning proposal: Replace prescriptive anti-slop defaults with game UI design grammar

Status: proposed; human review and merge required.

## Observed problem

The anti-slop framework declares contextual design but still mandates repeated layout ratios, token limits, animation behaviors, and one of six whole-game layouts, producing visually different skins over similar UI shells.

## Proposed improvement

Refactor anti-slop guidance around mechanic-state composition, a multidimensional design signature, per-screen layout recipes, anti-repeat comparison, and game-specific UX validation while preserving mobile, accessibility, compliance, and art-quality gates.

    Observation

    The user reported that games generated by the framework are poorly and identically designed even though the studio has an anti-slop rule. This is a reusable framework correction, not a one-game preference.

    Repository evidence

    - `.claude/rules/anti-slop-design.md` says design is contextual but still mandates a universal 60/30/10 layout, one dominant focal point, 1-2 accents, 4-6 type sizes, animated changing numbers, and a fixed required-screen list.
    - `.claude/docs/layout-archetypes.md` asks the pipeline to choose one of six whole-game layouts, and `.claude/skills/auto-idea/SKILL.md` calls changing that single archetype the main variation lever.
    - `.claude/agents/ui-programmer.md` repeats the 60/30/10 ratio, one-focus rule, universal animated numbers, and single-archetype implementation instructions.

    External comparison

    - Popular anti-generic frontend guidance improves results by inferring context and separating quality checks from optional aesthetics, but its web-specific bans and signature patterns cannot be copied into games as defaults.
    - Game UI/UX guidance emphasizes mechanic-first information priority, contextual HUD visibility, progressive disclosure, safe areas, responsive anchors, full input navigation, and verification across target viewports.

    Root cause and proposed remedy

    The framework confuses cohesion with uniformity and treats a small catalog of complete layouts as variety. Replace the style recipe with a game-specific experience thesis, multidimensional design signature, per-state composition map, compositional grammar, explicit anti-repeat comparison, and evidence-based validation. Keep mobile-first, accessibility, compliance, gambling truth, and the studio's art-rendering baseline as hard invariants.

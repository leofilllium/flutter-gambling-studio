    # Settings route retention: diagnosis and targeted mitigation

    Date: 2026-09-13. Flutter 3.44.5. Game: Joker's Encore.

    ## Reproduction and retained objects

    The profile Web probe opened Settings and returned to the game 30 times, collecting garbage between three-cycle samples. `production/playtest/20260913-final/profile-memory/evidence.json` records post-GC JavaScript heap growth from 20,028,716 to 48,968,880 bytes. DOM nodes stabilized at 107 and event listeners at 50. This was persistent retention, not simply increasing live DOM or a debug-only measurement.

    Heap snapshots `/tmp/encore-heap-before.heapsnapshot` and `/tmp/encore-heap-after.heapsnapshot` independently captured 30 route cycles. The after snapshot contains exactly 30 `_TheatreScreenState` and 30 `_SliderState` objects, compared with zero before. `_OverlayPortalState` count increases from 12 to 72; `PageRouteBuilder` increases from 3 to 33. Semantics configurations, render objects, focus nodes, and animation controllers accumulate with those retained route trees.

    Tracing strong edges from GC roots produces this owner chain:

    ```text
    WidgetsFlutterBinding
      → PipelineOwner
      → SemanticsOwner._traversalChildNodes
      → map key: _OverlayPortalState
      → OverlayPortal.overlayChildBuilder
      → _SliderState
      → Slider.onChanged / onChangeEnd
      → _TheatreScreenState
    ```

    This identifies a framework retention path rather than a missing application controller disposal.

    ## Installed framework source proof

    Under `/opt/homebrew/share/flutter/packages/flutter/lib/src/`:

    - `material/slider.dart:681` creates its value-indicator `OverlayPortalController` with `..show()`. `slider.dart:1009` unconditionally wraps the slider in `OverlayPortal`. A value-indicator theme setting cannot eliminate that portal.
    - `widgets/overlay.dart:2109` uses its `_OverlayPortalState` as the semantics traversal child identifier.
    - `semantics/semantics.dart:4997` stores that identifier as a strong map key in `_traversalChildNodes`.
    - `SemanticsNode.detach`, `semantics.dart:3278`, removes detached nodes from the map's value sets but does not remove empty keys. The analogous update cleanup at line 4946 also leaves keys behind.

    ## Application mitigation

    The Settings reminder slider is replaced with a gold `CupertinoSlider`, which does not create an overlay. It preserves configured bounds, integer-minute divisions, draft-on-drag behavior, and persisted changes on gesture completion. A 48-pixel control box, minute-based screen-reader values and increment/decrement actions, keyboard arrows, and a visible keyboard focus border preserve interaction and accessibility. Screen-reader changes commit immediately; this is explicitly adapted because Cupertino's built-in semantics invoke `onChanged` without `onChangeEnd`.

    The slider-only browser rerun did **not** close the issue: 30 cycles still grew from approximately 20 MB to 47.9 MB. `/tmp/encore-fixed-heap-after.heapsnapshot` retained another 30 Settings states through a second path:

    ```text
    SemanticsOwner._traversalChildNodes
      → map key: _OverlayPortalState
      → OverlayPortal.child
      → _ExclusiveMouseRegion → Listener → Semantics → MouseRegion
      → AnimatedTheme → InkWell.onTap
      → _TheatreScreenState_build__closure (Back navigation callback)
    ```

    The Back icon's Material tooltip created this second portal. All `StageIcon` controls now use explicit label, button, and enabled semantics merged with the native `IconButton` action/focus semantics. The tooltip is removed. Touch and keyboard behavior and 48×48 geometry remain intact; hover tooltip text is intentionally omitted to avoid this installed framework retention path. No unused tooltip remains for test selectors: existing navigation tests use public semantics labels.

    No Flutter SDK modifications, semantics disabling, art changes, mathematical changes, or screen redesigns were made.
